A SIMPLE GUIDE

Two processes. One helpful answer.

First prepare the hospital document. Then ask questions using that saved information.

Follow a question

  1. The browser sends your question to the local Python backend.
  2. LangGraph adds it to your conversation. The AI reads your history to understand follow-ups.
  3. The AI may reply with a greeting, clarification question, or scope explanation. There is no separate clarification node.
  4. For hospital facts, the AI writes a focused search query. The embedding model converts it into numbers, and Chroma finds up to six passages.
  5. The same chat model writes an answer using the current question, resolved tool call, and current retrieved passages. Older passages are excluded at this stage.
  6. The page displays the answer and references. Citation numbers restart for every response.

What is saved?

Chroma is the hospital index on disk. Conversation memory exists only in the Python server process. New Conversation selects a fresh ID; restarting the server clears all conversation state.

Embeddings find similar text. The LLM decides whether to search and writes answers. Optional LangSmith traces record activity for debugging; they do not supply hospital answers.

The real graph is prepare → agent → optional search → agent → finish. A hospital question uses at most one search. Evaluation lives in rag-pipeline/ and saves reports; exploring this chat does not replace those repeatable tests.
